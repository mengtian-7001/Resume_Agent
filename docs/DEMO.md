# 招聘筛选演示

按下面的路径走一遍完整筛选：上传 JD / 简历、查看匹配结果和质检意见，并在候选人详情里核对原文证据与面试准备材料。

## 演示目标

面向招聘人员与用人经理：系统不替代录用决策，而是用可追溯证据建立候选人优先级，缩短人工复核时间。现场要讲清楚的是「为什么是这几个人」，而不是再凭印象翻一遍简历。

## 无配置演示路径

1. 直接打开 `index.html`，页面显示「当前模式：静态产品示例」。
2. 点击「发起筛选」。
3. 点击「查看示例结果」：立即展示预制的 1 份 JD + 6 份简历结果，不调用 Worker。
4. 在「候选人」打开“陈思齐”：展示证据、风险、AI 质检、修正结论和面试准备材料。

真实演示使用 `./dev.sh` 启动后，选择样例 JD/简历并点击「一键解析」/「运行真实样例」。顶栏会显示「真实样例处理 · Mock Agent」或「真实模型处理 · OpenAI Agent」。

## 两分钟讲解顺序

| 时间 | 页面与讲述 |
| --- | --- |
| 0–15 秒 | 工作台：招聘人员面对大量非结构化简历，判断标准不一致、结论难追溯。产品目标是建立候选人优先级，不替代最终招聘决定。 |
| 15–35 秒 | 发起筛选：上传 1 份 JD 和多份简历，点击一次即可完成解析、匹配、质检，并生成面试准备材料。 |
| 35–75 秒 | 候选人列表：按推荐/复核/不匹配排序。说明分数由硬门槛、必备覆盖、项目相关度、生产实践和证据质量组成。 |
| 75–100 秒 | 候选人详情：展示原文证据、风险、针对性问题与追问，强调“为什么是这个优先级”。 |
| 100–115 秒 | AI 质检：展示推理路径、数据假设、问题严重程度与修正建议；例如预研不等于生产经验，因此由推荐降为人工复核。 |
| 115–120 秒 | 总结：AI 处理文档和同义技能理解，人仍负责验证自述与作出最终招聘决策。 |

## 使用边界

- 年限可由日期区间推断，属于假设，需人工确认相关性。
- 候选人自述与关键词出现不等于真实掌握；高风险能力需要项目原文、针对性问题和用人经理复核。
- 跨领域相邻技能可提高优先级，但不会静默绕过保存的硬门槛。

## 看什么指标

- 单份处理时间与端到端完成率。
- 推荐准确率、人工复核率、推荐误报率、拒绝误杀率。
- 证据覆盖率、Checker 发现的问题数，以及面试准备材料是否对准缺口。
